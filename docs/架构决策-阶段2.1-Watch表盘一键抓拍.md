# 阶段 2.1 架构决策：Watch 表盘一键抓拍

> 状态：已定案（2026-11-14，第 2 版 —— 推翻第 1 版的 watchOS 11 假设）
> 依据：Apple 官方文档 DocC JSON / Markdown 端点实测抓取，见文末「取证来源」。

## 0. 本文档修订记录

**第 1 版的错误**：假设 `ControlWidget` 在 watchOS 11 可用（因为 `AudioRecordingIntent` 是 watchOS 11）。
**实测结论**：`ControlWidgetButton` / `StaticControlConfiguration` / `ControlWidgetToggle` 的
DocC `metadata.platforms` **全部是 watchOS:26.0**。
⇒ 表盘「真·一键动作」在 watchOS 26 之前**根本不存在**。

## 1. 结论先说

**表盘一键抓拍在技术上成立**，官方机制是
**WidgetKit Control Widget（watchOS 26+）→ `AudioRecordingIntent`**。

但有 **三条硬约束**，共同决定了架构形态：

| # | 约束 | 官方依据 | 对架构的影响 |
|---|---|---|---|
| C1 | 采用 `AudioRecordingIntent` 后，**必须启动 Live Activity 并持续保持**，否则录音停止 | AudioRecordingIntent.md | 必须有 Live Activity 保活机制 |
| C2 | `LiveActivityIntent` 与 `Activity` 的 platforms **不含 watchOS** | DocC metadata.platforms | watchOS 侧**无法自己启动** Live Activity ⇒ 必须由 **iPhone 侧**启动 |
| C3 | `ControlWidget` 系列 API 的 platforms 是 **watchOS 26.0** | DocC metadata.platforms | 「表盘直接触发动作」需 watchOS 26+ |

C2 是最容易漏掉、且一旦漏掉就是「表盘按下去完全没反应」的坑。
C3 决定了 V1 的最低系统版本。

| API | watchOS 可用 | 最低版本 | 用途 |
|---|---|---|---|
| `AudioRecordingIntent` | ✅ | watchOS 11.0 | 表盘一键录音的官方协议（`SystemIntent` 子协议） |
| `ControlWidgetButton` | ✅ | **watchOS 26.0** | 表盘按钮控件 |
| `StaticControlConfiguration` | ✅ | **watchOS 26.0** | 无参控件配置 |
| `ControlWidgetToggle` | ✅ | **watchOS 26.0** | 表盘开关控件 |
| `WidgetFamily.accessoryCircular` | ✅ | watchOS 9.0 | 圆形表盘 complication 尺寸 |
| `WidgetFamily.accessoryRectangular` | ✅ | watchOS 9.0 | 矩形表盘 complication 尺寸 |
| `Link`（SwiftUI 视图内） | ✅ | watchOS 7.0 | 降级入口（跳 App） |
| `AppIntentConfiguration` | ✅ | watchOS 10.0 | **配置型** widget（不是动作入口） |
| `AppIntent.supportedModes` | ✅ | **watchOS 26.0** | 后台运行模式 |
| `AppIntent.openAppWhenRun` | ✅ | watchOS 9.0 | **已废弃**，官方要求改用 `supportedModes` |
| `LiveActivityIntent` | ❌ | — | 后台启动 Live Activity，watchOS 无此能力 |
| `Activity` / `Activity.request` | ❌ | — | watchOS 侧无法启动 Live Activity |

### 2.1 `supportedModes` / `openAppWhenRun` 的版本陷阱

官方文档明确 `openAppWhenRun` 已废弃：

> This property is deprecated. Use `supportedModes` instead.
> Setting this property to `true` generates an error if the app intent runs in an app extension.

而 `supportedModes` 的 platforms 是 `iOS:26.0 … watchOS:26.0`。

⇒ **V1 目标 watchOS 26+**（与 Control Widget 的门槛一致），此时可以直接用
`supportedModes = .background`，不必再走「不声明 `openAppWhenRun`」的老路径。
**但**代码仍保留 `#available` 分支，watchOS 11–25 上降级为不声明 `openAppWhenRun`，
避免低版本直接编译不过。

## 3. 架构

```
用户点表盘 complication
        │
        ▼
┌──────────────────────────────────────────┐
│ Watch: ControlWidget (accessoryCircular) │  WidgetKit Control Widget
│  → ControlWidgetButton(action: StartCaptureIntent()) │
└──────────────────────────────────────────┘
        │  (Watch 本地执行，不打开 App)
        ▼
┌──────────────────────────────────────────┐
│ Watch: StartCaptureIntent : AudioRecordingIntent │
│  1. CaptureSession.start()               │  ← 纯逻辑，在 DayEchoKit，已 194 项测试覆盖
│  2. WatchRecorder 起录                   │
│  3. 请求 iPhone 侧启动 Live Activity      │  ← 保活，见 C2
└──────────────────────────────────────────┘
        │  WatchConnectivity transferUserInfo
        ▼
┌──────────────────────────────────────────┐
│ iPhone: CaptureKeepAliveIntent           │  LiveActivityIntent
│  → Activity.request(...)                 │  ← watchOS 侧做不到，必须在 iPhone
└──────────────────────────────────────────┘
        │
        ▼  说完话静音 6s  /  到 120s 硬上限
┌──────────────────────────────────────────┐
│ Watch: 自动封条                          │
│  → 落盘 segment → WCSession 传 iPhone     │
└──────────────────────────────────────────┘
```

### 3.1 为什么倒计时是「硬上限」而不是「先到者」

★ 这是实现中发现的真实缺陷，已修 ★

第一版把倒计时写成 `min(最长剩余, 静音剩余)`。因为静音阈值固定 6 秒、恒小于最长时长 120 秒，
结果是：

- 倒计时**永远显示 6 秒**，用户一直说话时数字也不往下走；
- 「最长时长封条」这条分支**永远不会触发**。

正确语义是两条**独立**通道：

- **硬上限**（120 秒）：倒计时显示的就是它，用户看得见时间在走；
- **静音收尾**（6 秒）：说话结束后提前停止 —— 它是「提前结束」，不是「倒计时」。

对应实现：`CaptureSession.remainingSeconds()` / `CaptureSession.idleRemainingSeconds()`。

### 3.2 时长参数

| 参数 | 值 | 理由 |
|---|---|---|
| `minDuration` | 3 秒 | 低于此判误触，不产出候选 |
| `maxDuration` | 120 秒 | 用户说的「60–120 秒」上界 |
| `idleTimeout` | 6 秒 | 说完就停 |

### 3.3 降级路径（watchOS 11–25）

Control Widget 不可用时，提供一个 `accessoryCircular` 的普通 complication，
内部用 `Link` 跳进 App，App 打开后自动开始抓拍。

⇒ 功能降级为「一点 → 跳 App → 自动开始录音」，比 Control Widget 多一跳，但**不丢功能**。

## 4. 已被否决的路径

| 路径 | 否决理由 |
|---|---|
| watchOS 侧直接 `Activity.request` 起 Live Activity | **平台不提供**（`Activity` platforms 无 watchOS） |
| watchOS 侧用 `LiveActivityIntent` | **平台不提供**（`LiveActivityIntent` platforms 无 watchOS） |
| `AppIntentConfiguration` 当动作入口 | 它是**配置型** widget（给用户选参数），不是点一下就执行动作 |
| 用 `Link` 直接做「表盘一键录音」 | `Link` 只能跳 URL/开 App，无法触发 App Intent |
| 继续用 `openAppWhenRun = true` | 官方已废弃，且在 App Extension 中设 true 会报错 |
| 全天连续录音 | 已在 v3 文档移出 V1 |

## 5. 未验证 / 待真机确认

1. **watchOS 26/27 上 `AudioRecordingIntent` 在后台能否稳定跑满 120 秒** — 官方只说「不给 Live Activity 就停」，
   没说不给会立刻断。**必须在 Series 12 真机上验证**（用户设备：Apple Watch Series 12）。
2. **iPhone 侧起 Live Activity 能否可靠覆盖 Watch 的录音窗口** — 跨设备时序未实测。
3. **Control Widget 在表盘上的点击响应延迟** — 未实测。
4. **`AudioRecordingIntent` 是否触发系统录音指示灯/横幅** — 影响审核（2.5.14）。
5. **Control Widget 的 `kind` 标识与 `WidgetBundle` 注册方式** — 需在真机确认 complication 出现在表盘编辑列表。
