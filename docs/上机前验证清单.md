### 1.2 API 签名已对照 Apple 官方文档校正

以下 4 处**曾是硬错误**，在 watchOS 上会直接崩或功能失效，现已全部修正：

| # | 错误用法 | 正确用法 | 后果 |
|---|---|---|---|
| 1 | `WCSessionTransfer` | `WCSessionFileTransfer` | **类型不存在**，编译必炸 |
| 2 | `session(_:didReceive file:error:)` | `session(_:didReceive file:)` | 回调不触发，文件收不到 |
| 3 | `scheduleBackgroundRefresh(withIdentifier:)` 闭包 | `scheduleBackgroundRefresh(withPreferredDate:userInfo:)` + `WKApplicationDelegate` | 后台刷新永不触发 |
| 4 | `setTaskCompleted(success:)` | `setTaskCompletedWithSnapshot(false)` | 编译失败 |

### 1.3 4 个 Bug 的修复点

**Bug #1 时间戳计算**
- 旧：`startedAt + (elapsed - segmentSeconds)` → 每段 elapsed 都 ≈ segmentSeconds，
  于是**所有段的时间戳挤在同一处**，iPhone 上时间线彻底失真。
- 新：段起点 = 上一段的**封存时刻**（重新观测的 `Date()`），由 `SegmentClock` 维护，
  不重叠、不漂移、误差不随段数放大。
- 单测：`G1-1`（起点严格递增）、`G1-2`（差值线性增长，反推算法会平方级累积）。

**Bug #2 初始状态**
- 旧：落盘默认 `.recorded` → 保留策略可能把还没传出去的录音删掉。
- 新：默认 `.pending`；保留策略**只清 `.verified`**，
  `.pending` / `.inFlight` / `.transferred`（待 ACK） / `.corrupted` 一律保留。
- 单测：`G2-1`（默认态断言）、`G2-2`（四种状态都不被删）、`G2-3`（只有 verified 被清）。

**Bug #3 `.inFlight` 死锁**
- 旧：进程被杀后残留 `.inFlight`，重启后该段永远不会被重新投递 ⇒ 录音静默丢失
  （这正是 Auday 式卡死的机制）。
- 新：冷启动恢复入口（`PendingTransferQueue.decode`）自动把残留 `.inFlight` 打回 `.pending`；
  **运行期** `nextBatch` 绝不捞取正在传输中的条目（防重复投递）。
- 单测：`G3-1`（重置数量）、`G3-2`（运行期不捞）、`G3-3`（持久化往返后自动重置）、
  `G3-4`（不影响待 ACK 的段）。

**Bug #4 `stop()` 尾段丢失**
- 旧：`stop()` 只停录音器，**最后一段从来没被封存过** —— 每次停止录音，尾段直接丢失。
- 新：`stop()` 走 `RecordingSealer.endSessionAndSealTail()` 补封尾段；
  定时器切段与手动 stop() 都先问 sealer「轮得到你封吗」，
  撞车时只有一方真正封存 ⇒ 既不双封存，也不丢尾段。
- 单测：`G4-1`~`G4-6`（含「定时器先封后 stop() 不双封」「stop() 先封后定时器不双封」
  「定时器封段后 stop() 仍封尾段」三个关键路径）。

## 2. 上机必做验证（按顺序，共 6 步）

> 每步都写明了**怎么算通过**和**失败了怎么定位**。
> 前 3 步是硬门槛，必须全过才继续。

### 步骤 1：安装与启动（5 分钟）

1. 从 GitHub Actions 下载 `.ipa` 并安装到 iPhone。
2. iPhone 配对 Apple Watch，安装 watchOS App。
3. 打开 App → 进入手表 App → 点开始录音。

**通过判据**：手表上有录音波形/计时在走；iPhone App 端能同步看到手表在录音。

**失败定位**：
- App 装不上 → 检查 CI 产物是否上传成功（`gh run view <id>`）
- 手表 App 闪退 → 看 `gh run list` 里 CI 是否真编译通过；本机复现用
  `xcrun swiftc -parse Sources/DayEchoWatchApp/*.swift`（语法层）
- 录音按钮无反应 → 检查麦克风权限弹窗是否被拒（iPhone → 设置 → 隐私 → 麦克风）

### 步骤 2：分段时间戳连续性（10 分钟）★ 验 Bug #1

1. 手表上连续录 **5 分钟以上**（至少 5 段）。
2. 停止录音。
3. iPhone 端查看时间线/段列表。

**通过判据**：
- 每段的**起点严格递增**，间隔 ≈ 60 秒 ± 1 秒（不能全都挤在同一处）
- 段的时长 ≈ 60 秒，最后一段（尾段）是实际剩余秒数
- iPhone 端把段按时间排序，重叠/错位不明显

**失败定位**：若所有段时间戳相同 ⇒ `SegmentClock` 未生效，检查手表 App 版本是否为本 commit。

### 步骤 3：停止录音后尾段存在（3 分钟）★ 验 Bug #4

1. 录音 **2 分 30 秒**（录到第 2 段中途）。
2. 停止录音。
3. 立刻看 iPhone 端段列表。

**通过判据**：
- 段数 = 3（定时器封的 60 秒 + 60 秒 + stop 封的 30 秒尾段）
- 尾段时长 ≈ 30 秒，**不是 0**、**不是 60 秒**
- 段序号连续：0 → 1 → 2（无跳号）
- iPhone 端显示的**总时长 ≈ 150 秒**（与实际录音时长一致，不是只算满段）

**失败定位**：
- 尾段丢失（只有 2 段）⇒ `stop()` 未走 `finalizeTailSegment`，
  检查 `sealer.endSessionAndSealTail()` 的返回值
- 尾段重复（出现 2 个 30 秒段）⇒ 双封存，检查 `finalizeSegment` 是否也封了一遍
- 总时长偏小 ⇒ `SegmentClock.totalRecorded` 的累加逻辑被破坏

### 步骤 4：断连与重连补传（10 分钟）★ 验 Bug #3

1. 录音 3 分钟（保证有段待传）。
2. **关掉手表蓝牙**（或让 iPhone 远离 1 米+开飞行模式）。
3. 继续录 2 分钟。
4. 恢复蓝牙连接，等 2 分钟。

**通过判据**：
- 断连期间录的段**一条都不丢**，恢复连接后全部补传
- iPhone 端段总数 = 断连前 + 断连期间，无缺失
- 无重复音频（同一段不出现两次）

**失败定位**：
- 段卡在手表不传 ⇒ 检查 `WatchTransferChannel` 的 `transferFile` 是否在
  `activationState == .activated` 时才调用
- 重复音频 ⇒ 运行期 `nextBatch` 捞取了 `.inFlight` 条目，查 `G3-2` 逻辑是否被绕过

### 步骤 5：手表重启后恢复（5 分钟）★ 验 Bug #3 冷启动

1. 录音 3 分钟，中途**强制重启手表**（长按侧边键 → 重启）。
2. 等待手表恢复 + 重新连接 iPhone。
3. iPhone 端查段列表。

**通过判据**：
- 重启前已封的段**一条不丢**
- 重启后录音会话能正常开始新会话（序号不跳号）
- 待传队列清空（都传完了）

**失败定位**：
- 重启后段卡住不传 ⇒ 冷启动 `.inFlight` 未重置，查 `PendingTransferQueue.decode`
- 序号跳号 ⇒ `sequence` 与 `clock.sealedCount` 错位，查 `finalizeSegment` 里是否仍手动 `+1`

### 步骤 6：存储保留策略（3 分钟）★ 验 Bug #2

1. 录一段，等它传完（iPhone 端显示已接收）。
2. 手表 App → 设置 → 触发一次「清理未传输的旧录音」（若 UI 有该入口）。
3. 检查已传输的录音**仍在**。

**通过判据**：
- 只有**已确认传输成功**的录音被清理
- 手表上还有未传出去的段时，清理操作**不会删掉它们**

**失败定位**：未传段被删 ⇒ `RecordingStore.applyRetention` 的状态过滤条件写错，
对照 `G2-2` 的四种状态断言。
