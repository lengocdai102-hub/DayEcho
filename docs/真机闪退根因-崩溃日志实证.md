## 结论一：主 App 闪退 = dyld 找不到 framework（**证明**，非推测）

`DayEcho-2026-11-18-113708.000.ips`：

```json
"termination": {
  "code": 1, "flags": 518,
  "namespace": "DYLD",
  "indicator": "Library missing",
  "details": ["(terminated at launch; ignore backtrace)"],
  "reasons": [
    "Library not loaded: @rpath/DayEchoKit.framework/DayEchoKit",
    "Referenced from: <2905FA68-C137-392E-A05-777BE622D47C> .../DayEcho.app/DayEcho",
    "Reason: tried: '/usr/lib/swift/DayEchoKit.framework/DayEchoKit' (no such file, ...)"
```

- `procLaunch` → `procExitAbsTime` 相差 **69 ms** —— 启动即死。
- `usedImages` 里**没有** DayEchoKit —— dyld 根本没加载上去。
- `codeSigningTrustLevel: 4`、`codeSigningFlags` 正常 —— **不是签名问题**。

`DayEchoKit.framework` 没有被嵌进 `.app/Frameworks/`。
`gen_xcodeproj.rb` 里 `ios_target` 缺 **Embed Frameworks 阶段** ⇒ actal 只建了 framework 产物，没拷进 app bundle。

- `d132661`（11-18 12:06）`fix(build): 补上缺失的 Embed Frameworks 阶段，修掉真机启动即闪退`

## 结论三：Watch 上看不到 app = 两个**独立**原因

### 原因 A：SideLoadly 根本没拿到 Watch（**证明**）

- SideLoadly 状态库 `~/Library/Application Support/sideloadly/installations.db`
  - `device_watches` 表**行数 = 0**
  - `installations` 表只有 1 行：`com.dayecho.app.H98V6YZ5QL`（iPhone 段）
- SideLoadly 二进制日志字符串：`Failed to load known paired watches`、`NoPairedWatches`
- 设备上 `ideviceprovision list` 里 **watchkitapp 的 profile 计数 = 0**

⇒ Watch App 那段**压根没进设备**。不是「装上了但没图标」。

### 原因 B：bundle ID 断链（**证明**）

- SideLoadly 装出来的最终 ID：`com.dayecho.app.H98V6YZ5QL`（加 Team ID 后缀）
- fix3 包里 Watch 的 `WKCompanionAppBundleIdentifier` = `com.dayecho.app`（**重签前的值**）
- ⇒ 指针断裂，即使 Watch 段被装进去，watchOS 也认不出手机上的宿主 app

⇒ **必须用会重写 companion 指针的工具**（isideload 系会递归重写 Watch bundle id 并同步 companion 键；
SideLoadly 不重写 ⇒ 永远断链）。

## 已知缺口（未修，需留意）

**iOS 主 App 的 `UIBackgroundModes` 在产物里丢了。**

- 源码 `gen_xcodeproj.rb:538` 设了 `['audio', 'processing']`
- 生成的 pbxproj 里**确实有** `INFOPLIST_KEY_UIBackgroundModes = "audio processing";`
- 但 fix3 产物 `Payload/DayEcho.app/Info.plist` 里**没有** `UIBackgroundModes`

⇒ `INFOPLIST_KEY_UIBackgroundModes` 是**数组语义**，Xcode 的 `INFOPLIST_KEY_*` 系列只支持标量，
数组被静默丢弃（pbxproj 里存成了空格分隔的字符串 `"audio processing"`）。

**修法**：iOS 主 App 改用显式 `Info.plist`（`GENERATE_INFOPLIST_FILE = NO` + `INFOPLIST_FILE`），
在 plist 里写真正的 `<array><string>audio</string>...</array>`。

**影响**：后台录音 / 音频转写保活会失效。冷启动不受影响（闪退不是这个原因）。
`NSSupportsLiveActivities` 同样缺失 —— 但代码里 ActivityKit 只在 Widget extension 和
`CaptureKeepAlive.swift` 用到，需要单独评估是否影响 Live Activity。
