# DayEcho 复盘：为什么「编译通过」被当成了「功能验证」

> 复盘日期：2026-11-19
> 触发：连续两天在「装机」环节反复受阻（签名 / profile / Apple 账号），
> 而 App 本身能不能跑起来，从未被验证过。
> 结论先行：**过去四天的 CI 从未验证过「装上能不能启动」。这不是环境问题，是流程漏洞。**

---

## 0. 一句话

**我用了四天时间死磕「最难的路上真机」，却跳过了「最简单就能验证」的那条路。**

模拟器 runtime（iOS 26.3 / watchOS 26.2）在我折腾 Apple 账号之前就已经装在本机。
一条 `xcodebuild -destination 'platform=iOS Simulator'` 三分钟就能回答
「装上能不能启动」—— 不需要 profile、不需要证书、不需要 Apple 账号、不需要用户的 iPhone。

---

## 1. 事实时间线（全部有提交记录 / 日志佐证）

| 时间 | 事件 | 本质 |
|---|---|---|
| 11-16 | CI 已有「Build iOS app (simulator)」步骤 | ★ 用的是 `generic/platform=iOS Simulator`，**只编译不装** |
| 11-16～19 | `ci-linux.yml` 每天跑 | 只跑 **145 条纯逻辑单测**（Foundation-only，不碰 UIKit/ActivityKit/WatchKit） |
| 11-16～19 | `ios.yml` 因 macOS 额度耗尽被改为 `workflow_dispatch` | ★ **日常 push 根本不跑** iOS 构建 |
| 11-17 | App Group 从 `group.com.dayecho.shared` 改成带 Team ID 的值 | 提交 `3e0ca37`，**但没同步 `legal/assert_info_plist_keys.py`** |
| 11-19 | 移除未使用的 `UIBackgroundModes=processing` | 提交 `0a8fee9`，**同样没同步断言脚本** |
| 11-19 | App Group 不匹配 → 签名阶段才暴露 | 本该在「模拟器装上」就暴露 |
| 11-19 | 缺 watchOS profile → Watch 无法签名 | 本该在「模拟器跑 Watch」就暴露 |
| 11-19 | `ios.yml` 手动触发跑了一次 | ★ 跑到 `Assert Info.plist required keys` 就红 —— **那两条断言从 11-17 起就是红的** |

**最扎眼的一条**：11-17 和 11-19 我改了 plist 却没有同步断言脚本，
这个错误**在 CI 里躺了两天没人发现** —— 因为 iOS workflow 是手动触发的，
而我四天里只手动触发过几次，每次都在更早的步骤就红了，永远跑不到那一步。

⇒ 这本身就是「没有装机门禁」的直接后果：**断言脚本和真实产物脱节了两天才被看到。**

---

## 2. 根因：把四件事当成了两件事

我在汇报里一直在用「编译成功」这个说法，实际上它只覆盖了第一件：

| # | 环节 | 我这四天验证了吗 | 怎么验证才算数 |
|---|---|---|---|
| 1 | **编译通过** | ✅ 天天验 | `xcodebuild` 返回 0 |
| 2 | **签名通过** | ⚠️ 部分 | `codesign -v` + entitlement 对齐 profile |
| 3 | **装得上** | ❌ **一次都没有** | 真机 `devicectl` / 模拟器 `simctl install` |
| 4 | **跑得起来不崩** | ❌ **一次都没有** | 拉起进程 + 等 10s + 查崩溃报告 |

**我把第 1 项的结果，反复当成第 3、4 项的证据。**

这正是记忆里早就写下的那条：**「★装上≠能启动」**。
它被记成了「注意点」，而不是「**门禁**」。

### 更深一层：环境把我带偏了

| 表面现象 | 当时的解释 | 真实原因 |
|---|---|---|
| 两天都在搞签名 | 「装机需要签名」 | 模拟器**根本不需要签名** |
| 一直等 profile | 「Watch 要 watchOS profile」 | 模拟器上 Watch **也能跑** |
| 死磕 Apple 账号 | 「没 profile 就没法装」 | 模拟器**完全绕开 Apple 账号** |

签名是最难、最不可控、最容易出挫败感的环节。
一旦开始死磕它，我就会不自觉地**把所有精力都吸进去**，
而**没有退一步问「有没有一条不需要签名的路能回答同样的问题」**。

⇒ 这是本次复盘最该记住的一条：
**当你在最难的路上连续受挫时，先退一步找最简可解释的验证路径，
而不是加大力度继续攻。**

---

## 3. 如果没有 Xcode，这些问题什么时候会被发现？

**答案：永远不会被发现。**

因为整条链路上「装上能不能启动」这一环从来就是断的，
而它恰好是**唯一一个不需要 Apple 账号的验证环节**。
只要缺了它，任何签名/账号问题都会成为「唯一可走的路」，
于是全部注意力都被吸到那条路上。

各问题本该的暴露时机：

| 问题 | 现在的暴露方式 | 本该在什么时候暴露 |
|---|---|---|
| Info.plist 键缺失 / 类型错 | 断言脚本（但两天没跑到） | 模拟器装上就报错 |
| App Group 不匹配 | 签名阶段（`codesign` 拒绝） | 模拟器装上就报错 |
| 断言脚本与产物脱节 | ★ 手动触发 CI 后 | 每次 push 必跑 |
| 启动即崩溃（EXC_BREAKPOINT） | 完全没暴露 | 拉起 + 等 10s |
| Widget 独立进程秒崩 | 历史上踩过一次，靠真机 | 模拟器拉起 Widget 进程 |
| `UIBackgroundModes` 冗余 | 我静态分析推出来的 | 运行时行为观察 |
| Live Activity 起不来 | 完全没验证过 | 模拟器触发 Live Activity |

**⇒ 改进不是「以后更小心」，而是「让 CI 每天自动回答这个问题」。**

## 4. 已落地的改进（不是承诺，是已提交的东西）

### 4.1 新增装机+启动门禁：`legal/assert_simulator_install_launch.py`

```
装进模拟器 → 确认 LaunchServices 登记 → 拉起 → 等进程存活 → 查崩溃报告
```

**★ 为什么它不依赖签名 ★**

模拟器**不校验 provisioning profile**。
⇒ 这道门禁 **不依赖 Apple 账号、不依赖证书、不消耗真机、不需要用户在场**。
⇒ 可以每天跑，再也不会出现「卡在 profile 就什么都测不了」。

### 4.2 CI 接线：`ios.yml` 新增步骤 `Assert simulator install and launch`

接在「Build iOS app (simulator)」之后。
★ 关键修正：把 `generic/platform=iOS Simulator`（**只编译**）
换成具体设备 `iPhone 16e`（**真装真启动**）。

### 4.3 修正断言脚本脱节（`21c1d69`）

`UIBackgroundModes` 期望值、`WKCompanionAppBundleIdentifier` 期望值
与真实产物对齐 —— 这两条断言从 11-17 起就是红的。

### 4.4 汇报口径变更（本人纪律）

**「编译成功」「签名成功」「装上了」「跑起来了」「功能验收通过」——五件事分开说。**
任何一件不许替代另一件。

## 5. 仍然没解决的（不粉饰）

| 项 | 状态 | 原因 |
|---|---|---|
| 本地模拟器实跑 | ❌ 未拿到结果 | 本机当前图形会话无活动显示（`screencapture` 报 `could not create image from display`），Simulator GUI 起不来窗口 ⇒ `simctl install` 挂死。**改由 CI runner 验证**（runner 有完整图形环境） |
| Watch 模拟器验证 | ⏳ 待做 | 同上，走 CI |
| Widget 独立进程验证 | ⏳ 待做 | 需在模拟器上按需拉起 extension |
| 真机验证 | ❌ 未做 | iPhone 离线（`unavailable`，USB 未枚举） |
| watchOS profile | ❌ 缺失 | 需用户在 Xcode 手动登录一次 Apple ID（**我零账号操作**） |

---

## 6. 给下一个接手的人（也包括我自己）

1. **不要用「编译通过」汇报装机结果。** 五件事分开说。
2. **卡在签名/账号时，先找不需要签名的验证路径。** 模拟器永远在那儿。
3. **改了 plist / 源码 / 工程文件，同步跑一遍 `legal/` 下的断言脚本** —— 它们和真实产物脱节两天了。
4. **CI 的 `workflow_dispatch` 手动触发 = 门禁不存在。** 要么挂到 push，要么定期自动跑。
5. **断言脚本自己也要被验证。** 断言脚本错了，CI 全绿也说明不了任何事。
